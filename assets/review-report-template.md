# Skill 审查报告

> 默认使用下面的简短报告，用户要求完整报告或问题复杂时才展开后面的覆盖表。所有问题都保留证据；不为凑数量制造问题。规则见 `../references/skill-standard.md`。

## 默认报告

**结论：<暂可用 / 需先修复 / 信息不足>。** <一句话说明针对什么用途、为什么这样判断。主用途与降级用途有差别时说清楚。>

<最多 3 个优先问题，每个用普通话说明：>
- **<必须改 / 建议改 / 可选改进>：<问题>**。<实际影响>；<最小修复>。证据：<文件与行号或章节>。

<无已确认问题时写“本次范围内未发现需要修改的问题”，不要为了套模板填建议。P1 对应必须改、P2 对应建议改、P3 对应可选改进；未证实收益的建议另列，不能冒充已确认缺陷。>

<最后只说明实质影响结论的范围与未验证内容，如“本次只读检查，未验证真实工具执行”。有关键未知时说明怎样取得证据；不把调查工作转嫁成一长串用户问卷。>
