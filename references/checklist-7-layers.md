# 通用与场景检查清单

本清单按 `skill-standard.md` 执行。文件名保留便于已有引用继续使用；七层仅供末尾定位，不是必填目录或评分框架。

## 通用检查

每项记录：适用条件、通过 / 有问题 / 不适用 / 待确认、证据与影响。标题、步骤数、文件数量不能代替判断。

### 选择与边界
- 自动发现或显式调用的描述是否足以帮助选择任务？不用固定句式；若目标平台有元数据要求，核对实际平台约束，不把可选字段或未知扩展判错。
- 能力范围、必要输入是否可理解？只有容易误触发的邻近场景才需要明确排除。

### 执行指导
- 能否根据说明决定动作、顺序和必要分支？创作类允许以目标与判断标准指导，不强制流水线。
- 有没有只有原作者知道的账号、路径、习惯或“上次那个模板”？按共享范围判断是否造成阻塞。
- 是否把关键判断留成无法执行的“看情况处理”，又没有标准或示例？

### 输出与验收
- 输出对象、格式或质量要求是否能让使用者确认完成？示例、人工检查、断言均可能合适。
- 要求的检查能否做到，示例是否与规则一致？未执行检查时是否避免声称通过？

### 一致性与资源
- 必须读的文件、必须跑的入口是否按宿主的路径基准或运行时机制可取得？有无互相冲突的指令或优先级？先区分静态文件缺失、动态占位与审查环境不可见。
- 未直接链接的文件是否被二级引用、目录路由或工具使用？确认后再认定无用。
- 大段内容是否妨碍抓住必需动作？行数仅作线索，不自动要求拆分。

### 依赖与异常
- 必要工具、参数或运行环境是否可获得、可理解？环境未知与说明缺失分别记录。
- 缺信息、文件不可用或任务无法完成时，是否有与任务相称的处理方式？无需为简单任务凑异常数量。

## 场景项：只检查实际涉及的部分

| 条件 | 核对内容 | 不适用示例 |
|---|---|---|
| 创作与写作 | 受众、风格、内容约束、缺背景时的选择 | 不需要自动化测试目录 |
| 领域知识与研究 | 结论依据、来源可追溯、资料不足时保留判断 | 不凭结构认证医学、法律等领域准确性 |
| 重复计算、转换或 API 调用 | 参数、成功信号、错误处理、可靠执行方式 | 一次简单工具调用无需强制增加脚本 |
| 写入、发布、发送或删除 | 实际作用范围、授权、重复调用后果及必要恢复 | 纯只读分析无需回滚方案 |
| 定时或事件触发 | 运行宿主或调度机制是否存在 | 人工调用无需 cron |
| 共享或长期维护 | 跨环境依赖、可变接口来源、何时更新 | 短期个人写作无需 CHANGELOG |

## 可选七层定位

只在帮助解释问题时使用：触发（选择）、编排（执行指导）、执行（工具与脚本）、知识（参考依据）、资产（模板与样例）、验证（结果检查）、维护（环境与演化）。

同一文件可承担多层职责。缺少独立目录不是缺陷；只有实际需要的能力缺失且能说明影响时才报告。
